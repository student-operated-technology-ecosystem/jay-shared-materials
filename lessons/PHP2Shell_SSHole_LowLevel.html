The PHP Situation

PHP is a component of many applications on the Internet. What are the implications of an issue like this?

Supplemental Information

  • Like many systems and infrastructure applications, PHP is implemented in the C Programming Language
  • freeing memory is a requirement of languages which do not automatically manage dynamic memory. This is the case in C, and the programmer is responsible for correctly allocating memory and freeing it.
  • The struct conversation has some deeper technical implications, but here is some info:
    • Low Level says structs are two items conjoined, but a struct can have any number of members
    • Components of C structs are arranged contiguously in memory -- the speak will always be next to the name, and they'll be in the order they're listed in for the struct declaration.
    • A function pointer has the ability to change where a program will execute its next instructions. If you can rewrite that, you can move the program anywhere, and might even be able to execute some data as if it were code.
  • Address Sanitizer, or ASan, is a compiler function which can detect when dynamic memory is used improperly. Many programs will continue to function in a double free or use after free situation, but not if they're compiled with Address Sanitizer. We often turn this off for optimized release builds, but use it for debugging builds.
  • Fuzzing is the practice of testing a program by passing huge amounts of randomized input data to it.
  • Pay close attention to the discussion about how AI finds certain bugs humans cannot.
  • Rust is a language which aims to provide the functionality of C with features that make it easier to build safe programs with it. The question of "Would Rust have fixed this?" has implications about the different memory models each language uses, and is a common question when assessing vulnerabilities.

The SSH Situation

The OpenBSD team, which also produces OpenSSH, is one of the most disciplined software engineering teams practicing the art today. OpenSSH can be held up as an example of impeccably secure and correct software. What's going on here?

Supplemental Information

  • The library mentioned is pronounced "mussel C". The logo is a shellfish. Not an oyster, not a clam, a mussel.
  • glibc and musl_libc are two competing implementations of the C standard library
  • Musl is a smaller and optimized version of libc, but users of it should be aware it is not perfectly equivalent to glibc
  • The decision to avoid returning NULL to stop programs from crashing should be criticized. Conventional wisdom is that we want programs to crash rather than continuing in an invalid state. Compare this to how the use-after-free situation performs with or without ASan enabled.
  • Take time to really understand what's going on with the timing attack! It's an awesome class of sidechannel attack to be aware of. What's going on here is that cryptographic operations take a lot of time compared to just returning failed lookup. If we recognize that a user login with a certain username takes a longer time than others, we know that username exists. Timing attacks exist in many places and in many other forms -- learn to recognize them!
  • Low Level initially says Rust would not fix this issue before mentioning some possibilities referring to language features like enums. These features in a static typing context are also available in C. Whether or not C programmers use them as frequently as Rust programmers might be a different story, but the answer you should take from his explanation is no, Rust would not have fixed this issue -- unlike the PHP example.
